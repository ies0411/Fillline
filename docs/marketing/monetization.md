# 수익화 검토 — 무료 배포를 유지하면서 "용돈" 만들기

작성 2026-10-21. 목표는 생계가 아니라 **월 1만~20만원 수준의 부수입**이며, 배포는 무료를 유지한다.
이 문서는 후보를 비교하고 **실행 순서**를 정한다.

## 0. 전제(바꾸지 않는 것)

| 제약 | 이유 |
|---|---|
| 소스는 MIT로 공개, 무료 | 프로젝트 정체성. 유료화는 "코드"가 아니라 "편의"에 붙인다 |
| 텔레메트리·애널리틱스 없음 | 제품 주장의 핵심. 여기에 광고/추적을 붙이면 제품이 자기모순이 된다 |
| 백엔드 없음 | 운영비 0 유지. 라이선스 검증도 오프라인 |
| Mac App Store 불가 | 샌드박스 해제 필요(`~/.claude`·`~/.codex` 읽기) |
| 제품명에 provider 상표 금지 | Claude/Codex/OpenCode/Google |

## 2. 권장 순서

**Phase A — 지금 (비용 0)**
- README에 `Support` 섹션 + GitHub Sponsors 링크. 앱 설정에도 "Support Fillline" 링크 하나.
- 추적 파라미터 없음(UTM 금지). 유입은 GitHub Referrers로만 본다.
- 기대 매출: **0원**. 목적은 "돈 받을 수 있는 프로젝트"라는 신호.

**Phase B — v0.3.0(서명 릴리스) 직후**
- **Supporter build**를 Polar에 등록: `$9` 최소, pay-what-you-want 허용.
  - 무료: 소스 빌드 + ad-hoc 알파(GitHub Releases)
  - 유료: **notarized DMG + Sparkle 자동업데이트 + 우선 지원**
- 라이선스 검증은 오프라인: Ed25519 공개키를 앱에 내장하고, `license.json`(서명된 payload)을 로컬에서 검증.
  네트워크 호출 없음 → "no telemetry" 유지.
- Homebrew cask는 **무료 빌드만** 가리킨다(유료 연결 금지, cask 정책상으로도 깔끔).

**Phase C — 수요가 확인되면(Supporter 10건+)**
- Pro 기능($19): CSV/JSON 내보내기, 히스토리 30일, 임계값 프리셋, 메뉴바 스타일.
- 여전히 **provider 접근 자체는 무료**. quota를 paywall 뒤에 두면 MIT 정신과 상표/ToS 리스크가 동시에 나빠진다.

## 3. 숫자 감각 (정직하게)

- 개인 개발자용 dev tool의 다운로드→유료 전환은 대략 **0.3~2%**.
- HN 1면 + r/macapps 노출 시 3~10k stars, 초기 다운로드 수천 건은 가능하지만 **대부분은 무료 사용자**다.
- 보수 시나리오: 월 1,000 다운로드 × 0.5% × $9 ≈ **월 $45**(세전, 약 6만원).
- 낙관 시나리오: 월 5,000 다운로드 × 1.5% × $9 ≈ **월 $675** — 현실적으로는 1년차에 드물다.
- **고정비부터 넘어야 한다**: Apple Developer Program **$99/년**. 즉 연 $99를 못 넘으면 마이너스다.

## 4. 결제·유통

| 선택지 | 수수료 | 특징 |
|---|---|---|
| **Polar** | ~4% + $0.40 | OSS 친화, Merchant of Record(세금 대행), GitHub 연동, 라이선스 키 API |
| Lemon Squeezy | ~5% + $0.50 | UX 좋음, MoR |
| Paddle | ~5% + $0.50 | B2B에 강함, 심사 있음 |
| Gumroad | 10% | 가장 간단, 수수료 높음 |

→ **Polar** 권장. 단, 라이선스 키 발급 API를 쓰더라도 **앱은 네트워크로 검증하지 않는다**
(구매 시 받은 서명 파일을 로컬 검증). 이 원칙을 어기면 제품 주장이 무너진다.

## 5. 법·세무 (한국, 요약)

- 수익 성격: 반복 판매면 **사업소득**(간이과세/일반), 단발 팁은 기타소득으로 처리되는 경우가 있다.
  월 매출이 소액이라도 **연 단위 신고 대상**이 될 수 있으니 첫 수익 발생 시 세무사 확인 1회 권장.
- Polar/Lemon Squeezy가 MoR이면 **해외 부가세는 대행**되지만, 국내 소득 신고 의무는 별개다.
- MIT는 판매를 허용한다. 단 소스 공개 의무는 유지되므로 "유료 = 빌드/지원", "무료 = 소스" 구조가 안전하다.
- 상표: 유료 판매 페이지에도 "not affiliated with Anthropic/OpenAI/OpenCode" 고지를 유지한다.

## 6. 하지 않을 것

- 앱 내 광고, 애널리틱스 SDK, UTM, 크래시 리포트 SaaS(Sentry 등) — 제품 주장과 정면 충돌
- provider quota 접근을 유료 전용으로 잠그기 — MIT 정신 + ToS/상표 리스크
- 자격증명을 서버로 중계하는 "클라우드 동기화" — 보안 사고 시 프로젝트 종료급
- "lifetime license"를 근거 없이 약속하기 — 유지보수 중단 시 신뢰 붕괴
- 별점/리뷰 대가 프로모션 — GitHub/커뮤니티 정책 위반 소지
